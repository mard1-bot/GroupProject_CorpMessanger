## Описание проекта

Проект представляет собой **Корпоративный мессенджер**, предназначенный для защищённого обмена сообщениями, управления пользователями и чатами, хранения истории переписки, передачи файлов и администрирования внутри организации.

Основная цель проекта — разработка программного решения, обеспечивающего удобную и безопасную корпоративную коммуникацию с учётом требований законодательства Российской Федерации в области обработки персональных данных и информационной безопасности.

## Цели разработки

В рамках проекта предполагается создание системы, обеспечивающей:

- обмен сообщениями в реальном времени;
- управление пользователями;
- создание и сопровождение чатов;
- хранение и поиск сообщений;
- передачу файлов;
- отправку уведомлений;
- администрирование пользователей и ролей;
- архивирование и аудит действий;
- защиту данных и разграничение прав доступа.

## Основной функционал

Система должна поддерживать следующие функции:

1. **Передача сообщений**  
   Обеспечение обмена сообщениями между пользователями в рамках личных и групповых чатов.

2. **Управление пользователями**  
   Регистрация, хранение и сопровождение пользовательских данных, а также управление учётными записями.

3. **Управление чатами**  
   Создание, изменение и сопровождение диалогов и групповых чатов.

4. **Хранение и поиск сообщений**  
   Сохранение истории переписки и реализация механизмов поиска по сообщениям.

5. **Передача файлов**  
   Поддержка отправки и получения файлов в рамках диалогов и чатов.

6. **Уведомления**  
   Информирование пользователей о новых сообщениях и событиях системы.

7. **Администрирование**  
   Блокировка и удаление аккаунтов, управление ролями и доступами.

8. **Архивирование и аудит**  
   Хранение переписки в соответствии с политиками компании, экспорт переписок, аудит действий и метаданных.

9. **Информационная безопасность**  
   Шифрование данных, разграничение прав доступа, ограничение числа запросов и защита инфраструктуры.

## Работа с персональными данными

В рамках проекта предполагается обработка персональных данных пользователей. Возможные персональные данные, используемые в системе:

- фамилия, имя, отчество;
- адрес электронной почты;
- номер телефона;
- переписка пользователей, если она позволяет идентифицировать участников.

### Подход к защите данных

Персональные данные должны храниться в **зашифрованном виде** в базе данных.  
Для хранения данных в проекте используется **PostgreSQL**.  
Для защиты передачи данных используется протокол **TLS**.

## Нормативные требования

При проектировании и разработке системы учитываются положения Федерального закона:

**Федеральный закон от 27.07.2006 № 152-ФЗ «О персональных данных»**

### Ключевые положения, учитываемые в проекте

1. Обработка персональных данных допускается при наличии письменного или электронного согласия субъекта персональных данных.
2. Персональные данные не подлежат раскрытию третьим лицам без законных оснований.
3. Сбор и первичное хранение персональных данных должны осуществляться в базах данных, расположенных на территории Российской Федерации.

## Технологический стек

В проекте используется следующий стек технологий:

- **React Native** — клиентская часть приложения;
- **Go** — серверная часть приложения;
- **Figma** — проектирование пользовательского интерфейса;
- **PostgreSQL** — база данных;
- **XMPP (ejabberd) с расширением UMC** — протокол и сервер обмена сообщениями;
- **TLS** — защита передачи данных.

## Быстрый старт

### Требования

- Docker и Docker Compose
- Node.js 18+ (для разработки frontend)
- Go 1.21+ (для разработки backend)

### Установка

1. **Клонируйте репозиторий**
   ```bash
   git clone https://github.com/mard1-bot/GroupProject_CorpMessanger.git
   cd GroupProject_CorpMessanger
   ```

2. **Настройте переменные окружения**
   ```bash
   cp backend/.env.example backend/.env
   cp client/.env.example client/.env
   # Отредактируйте backend/.env и client/.env с вашими значениями
   ```

3. **Настройте TURN сервер для WebRTC (обязательно для звонков)**
   - Установите `TURN_EXTERNAL_IP` в `backend/.env` (ваш публичный IP или localhost для dev)
   - Установите `TURN_USERNAME` и `TURN_PASSWORD` в `backend/.env`
   - В `client/.env` установите те же значения для `EXPO_PUBLIC_TURN_*`

4. **Запустите через Docker Compose**
   ```bash
   docker-compose up -d
   ```

5. **Установите пароль администратора**
   ```bash
   cd backend/cmd/setadminpass
   go run main.go "YourSecurePassword123!"
   ```

6. **Запустите клиент (для разработки)**
   ```bash
   cd client
   npm install
   npm start
   ```

### Доступ

- **Backend API:** http://localhost:8080
- **Frontend:** http://localhost:19006 (Expo)
- **PostgreSQL:** localhost:5432
- **TURN Server:** localhost:3478

### Настройка HTTPS (для production)

WebRTC требует HTTPS в production. Для включения:

1. **Сгенерируйте сертификаты**
   ```bash
   mkdir -p certs
   openssl req -x509 -newkey rsa:4096 -keyout certs/server.key -out certs/server.crt -days 365 -nodes
   ```

2. **Включите TLS в backend/.env**
   ```
   TLS_ENABLED=true
   TLS_CERT_PATH=/app/certs/server.crt
   TLS_KEY_PATH=/app/certs/server.key
   ```

3. **Перезапустите docker-compose**
   ```bash
   docker-compose down
   docker-compose up -d
   ```

### Групповые звонки (LiveKit)

Для групповых звонков включите LiveKit:
```bash
docker-compose --profile with-livekit up -d
```

### Без LiveKit

P2P звонки работают без LiveKit через TURN сервер. Для минимальной конфигурации:
```bash
docker-compose up -d  # без LiveKit
```
